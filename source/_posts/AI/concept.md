# AI 概念

这篇不是介绍“什么是人工智能”，而是给刚开始用 AI 的人解释常见术语。很多人第一次付费 AI 时最困惑的不是“AI 能不能回答问题”，而是：为什么同一个 AI 有这么多版本？为什么同样付费，还要区分普通模式、思考模式、High 模式？为什么 ChatGPT、Codex、Sora 都是 OpenAI 的产品，却不是一个东西？

## 模型

模型就是 AI 的“大脑”。不同模型的能力、速度、价格、上下文长度都不一样。

| 差异 | 小白理解 |
| --- | --- |
| 大模型 | 更聪明，适合复杂推理、长文、代码架构、疑难问题 |
| 小模型 | 更便宜更快，适合改句子、总结、翻译、简单问答 |
| 推理模型 | 会花更多时间思考，适合数学、逻辑、规划、复杂代码 |
| 多模态模型 | 能处理文字、图片、音频、视频中的一种或多种 |
| 长上下文模型 | 能一次读更多文件、更多聊天记录、更多资料 |

不要默认“最高级模型永远最好”。高级模型的成本更高，响应更慢，有时还会为了严谨而显得啰嗦。简单任务用高级模型，相当于用大型工程队修一个松动的螺丝。

## 模式

很多产品会提供普通、Thinking、High、Pro、Deep Research、Max 等模式。它们通常不是“答案风格”的区别，而是资源投入不同。

| 模式 | 适合场景 | 不适合场景 |
| --- | --- | --- |
| 普通模式 | 日常问答、改文案、翻译、快速解释 | 多步骤推理、复杂代码 |
| Thinking / Reasoning | 逻辑题、方案比较、复杂 Bug、架构设计 | 简单聊天、短文本润色 |
| High / Pro | 高难度推理、长时间编码、研究型任务 | 随手问一句、低价值任务 |
| Deep Research | 需要引用来源、跨网页整理资料 | 只需要常识答案 |
| Agent 模式 | 让 AI 持续执行任务，比如改代码、跑命令、整理文件 | 权限不明确、目标不清楚的任务 |

为什么不一直用 High 模式？

1. 更贵：订阅产品会消耗更多配额，API 会消耗更多费用。
2. 更慢：它会投入更多计算，等待时间更长。
3. 不一定更准：简单任务里，更多推理可能带来过度分析。
4. 更容易碰到限制：高级模式通常有更严格的次数、速度或并发限制。

小白可以这样选：简单问题用普通模型，重要决策用推理模型，长资料用长上下文模型，查资料用联网或研究模式，执行任务用 Agent。

## 上下文

上下文就是 AI 当前能“看见”的内容，包括你的问题、历史对话、上传文件、代码文件、网页资料等。

上下文越长，AI 能参考的材料越多，但成本也更高。上下文太乱时，AI 反而容易抓错重点。

使用建议：

1. 开新任务时新建对话，不要把所有问题塞进一个长会话。
2. 让 AI 先总结当前任务，再继续执行，避免它记偏。
3. 上传资料时告诉它“哪些是重点，哪些只是背景”。
4. 代码任务里让 AI 先读目录结构，再指定要改的文件范围。

## Token

Token 是 AI 计费和计算的基本单位，可以粗略理解成“字和词的小片段”。输入越长、输出越长，消耗的 token 越多。

对使用者的意义：

1. 长文档、长代码、长聊天会更贵。
2. 让 AI 输出几千字，比让它输出要点更耗配额。
3. 同样价格下，小模型能处理更多请求，大模型更适合少量高价值任务。

## 配额

配额是产品限制你使用量的方式。它不一定只看“问了几次”，还可能看模型、token、文件大小、图片数量、联网次数、并发任务、运行时长。

| 配额类型 | 例子 |
| --- | --- |
| 消息次数 | 每几小时或每月可问多少次 |
| 高级模型次数 | 高等级模型单独限制 |
| 深度研究次数 | Deep Research 每月有限 |
| 文件上传 | 单文件大小、文件数量、总容量 |
| Agent 用量 | 按请求数、token、运行时长或计算额度消耗 |
| API 限速 | 每分钟请求数、每分钟 token 数 |

所以买 AI 不能只看“每月多少钱”，还要看你最常用的功能是不是被单独限额。

## Agent

Agent 可以理解成“会自己拆任务并调用工具的 AI”。普通聊天是你问一句它答一句；Agent 更像你给一个目标，它会读文件、写代码、运行命令、查资料、整理结果。

Agent 的关键不是更会聊天，而是能行动。

适合 Agent 的任务：

1. 修改一个项目里的多个文件。
2. 查 Bug、跑测试、修复报错。
3. 整理资料并生成文档。
4. 执行重复流程，比如发周报、整理文件、同步表格。

使用 Agent 要注意权限。它能读写文件、联网、运行命令时，效率更高，风险也更高。第一次使用建议让它每一步都确认；熟悉后再开放更高权限。

## Skill

Skill 是给 AI 的“专项说明书”或“插件能力”。它告诉 AI 在某类任务中应该按什么流程做、用什么工具、遵守什么规则。

| Skill | 作用 |
| --- | --- |
| 写作 Skill | 固定文章结构、语气、SEO 规则 |
| 代码 Skill | 固定项目规范、测试方式、提交格式 |
| 图片 Skill | 生成统一风格的封面、插图、头像 |
| 数据 Skill | 固定清洗、分析、导出流程 |

小白可以把 Skill 理解成“把经验写成可复用提示词”。当一个任务会重复做，就值得沉淀成 Skill。

## MCP

MCP 是一种让 AI 连接外部工具和数据源的协议。你可以把它理解成 AI 的“插线板”。通过 MCP，AI 可以接入数据库、GitHub、浏览器、文件系统、设计工具、企业系统等。

没有 MCP 时，AI 只能根据你贴给它的内容回答。接上 MCP 后，它可以在授权范围内读取真实数据、调用真实工具。

使用建议：

1. 只连接真正需要的工具。
2. 不给 AI 超出任务范围的权限。
3. 对公司代码、客户数据、账号密钥保持谨慎。

## RAG

RAG 是“检索增强生成”。简单说，就是先从资料库里找相关内容，再让 AI 根据找到的资料回答。

它解决的问题是：AI 自己记不住你的私有资料，也可能不知道最新信息。RAG 让 AI 回答时参考指定知识库。

适合场景：

1. 公司内部知识库问答。
2. 法规、手册、产品文档查询。
3. 客服机器人。
4. 私人笔记搜索。

## API

API 是给开发者调用模型的接口。普通用户买 ChatGPT、Claude、Gemini 会员，是在用“成品应用”；开发者用 API，是把模型接进自己的软件。

| 项目 | 订阅产品 | API |
| --- | --- | --- |
| 付费方式 | 按月订阅为主 | 按 token、图片、音频、工具调用等计费 |
| 使用方式 | 网页、App、客户端 | 写代码调用 |
| 适合人群 | 普通用户、创作者、学生、开发者个人 | 开发者、公司、自动化系统 |
| 优点 | 开箱即用 | 可集成、可自动化、可控性强 |
| 缺点 | 配额和功能由平台决定 | 需要开发能力，成本要自己控制 |

## 同一家公司不同 AI 产品的区别

很多公司会把同一个底层模型做成不同产品。它们不是重复，而是面向不同使用场景。

| 产品形态 | 代表 | 主要用途 |
| --- | --- | --- |
| 聊天助手 | ChatGPT、Claude、Gemini | 问答、写作、学习、分析 |
| 编程 Agent | Codex CLI、Claude Code、Gemini CLI | 读代码、改代码、跑命令、修 Bug |
| IDE 插件 | GitHub Copilot、Cursor、Codeium | 写代码时补全、解释、重构 |
| 搜索型 AI | Perplexity、秘塔、Kimi 搜索 | 查资料、找来源、做信息汇总 |
| 视频/图片工具 | Sora、Veo、Midjourney、即梦 | 生成图片、视频、视觉素材 |
| 自动化平台 | OpenClaw、小龙虾类本地 Agent | 接入工具、消息渠道、定时执行任务 |

选择时不要只问“哪个 AI 最强”，要问“我要在哪个工作流里用它”。写代码的人需要 IDE 或命令行，查资料的人需要搜索和引用，做短视频的人需要图像和视频模型。

## 小白选择原则

1. 先用免费版体验 3 天，确认自己每天真的会用。
2. 第一个付费产品优先选通用聊天助手，不要一开始就买多个。
3. 写代码多，再补一个编程工具。
4. 查资料多，再补一个搜索型 AI。
5. 只有当你经常撞配额，才升级到更高套餐。
6. 不要迷信排行榜，排行榜只能说明某些测试强，不代表适合你的日常任务。
