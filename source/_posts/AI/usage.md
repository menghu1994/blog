# AI 使用指南

所有 AI 理论上都可以做很多事：写文章、写代码、翻译、总结、查资料、做表格、生成图片、规划方案。但每种 AI 都有更擅长的方向。会用 AI 的关键不是只找一个“最强 AI”，而是知道什么时候用哪个，以及怎么让它们相互配合。

## 最重要的原则

AI 使用质量主要由三件事决定：

1. 你给的目标是否清楚。
2. 你给的背景是否足够。
3. 你有没有检查和迭代。

不要只说“帮我写一篇文章”“帮我修代码”。更好的说法是：我要给谁看、希望达到什么效果、有哪些限制、输出成什么格式。

## 通用提示词结构

小白可以直接套这个结构：

```text
你是一个【角色】。
我要完成【目标】。
背景信息是【资料/现状】。
限制条件是【长度/风格/技术栈/预算/时间】。
请输出【格式】。
如果信息不够，请先问我最多 3 个关键问题。
```

例子：

```text
你是一个面向新手的前端老师。
我要理解 Vue Router 的导航守卫。
背景是我会 Vue 基础，但没做过权限控制。
限制是不要使用太多专业术语，每个概念都给一个小例子。
请输出一篇适合博客的 Markdown。
```

## 写作怎么用

适合工具：ChatGPT、Claude、Gemini、Kimi。

流程：

1. 先让 AI 帮你列大纲。
2. 你删掉不需要的部分。
3. 再让 AI 按大纲写第一版。
4. 让 AI 按你的语气改。
5. 最后人工检查事实和表达。

好用提示：

```text
请站在 AI 小白角度写，不要堆术语。每个专业词先用生活化比喻解释，再给正式解释。
```

```text
这段内容太像 AI 写的。请改得更像个人博客：句子短一点，少用口号，多用具体场景。
```

## 学习怎么用

适合工具：ChatGPT、Claude、Gemini。

学习不要只让 AI 给答案，要让它帮你搭台阶。

推荐方式：

1. 让 AI 先解释概念。
2. 让它给最小例子。
3. 让它出练习题。
4. 你回答后让它批改。
5. 让它总结错题。

提示词：

```text
请用费曼学习法教我这个概念。先用一句话解释，再用生活例子解释，然后给一个最小代码示例，最后问我 3 个检查理解的问题。
```

## 查资料怎么用

适合工具：Perplexity、Kimi、秘塔、ChatGPT/Claude/Gemini 的联网或研究模式。

查资料时要明确要求来源。

提示词：

```text
请帮我调研【主题】。要求：
1. 优先使用官网、文档、论文或权威媒体。
2. 每个关键结论都给来源链接。
3. 区分事实、推测和你的建议。
4. 最后给我一个适合小白的结论。
```

注意：

1. 最新价格、政策、版本必须查官网。
2. 不要只看 AI 总结，要点开来源验证。
3. 重要内容至少用两个来源交叉确认。

## 写代码怎么用

适合工具：Cursor、GitHub Copilot、Claude Code、Codex CLI、Gemini CLI。

### 小改动

比如改一个函数、修一个报错、写一个组件。

提示词：

```text
请只修改【文件路径】。
目标是【具体目标】。
不要改无关文件。
修改后说明你改了什么，并告诉我需要运行什么命令验证。
```

### 大改动

比如重构、加功能、跨多个模块。

流程：

1. 让 AI 先读项目结构。
2. 让它给修改计划。
3. 你确认范围。
4. 分步骤修改。
5. 每步跑测试或构建。
6. 最后人工 review diff。

提示词：

```text
请先不要修改文件。先阅读项目结构，告诉我这个功能可能涉及哪些文件、风险是什么、你建议分几步做。
```

### 代码安全底线

1. 改代码前先提交或开分支。
2. 不要让 AI 直接处理生产数据库。
3. 不要把密钥贴给 AI。
4. 不懂的命令不要让 AI 自动执行。
5. 任何安全、支付、权限相关代码都要人工复查。

## 让多个 AI 相辅相成

不要让一个 AI 做所有事。更高效的方式是分工。

### 写文章组合

1. 搜索型 AI：收集资料和来源。
2. Claude / ChatGPT：整理大纲和初稿。
3. Gemini / ChatGPT：补充例子和图表思路。
4. 自己：检查事实、加入个人经验。

### 写代码组合

1. Cursor / Copilot：日常补全和小修改。
2. Claude Code / Codex CLI：处理多文件任务。
3. ChatGPT / Claude：讨论架构和解释报错。
4. 搜索型 AI：查官方文档、版本变化、报错资料。

### 学习组合

1. ChatGPT / Claude：当老师讲概念。
2. Gemini / NotebookLM：整理资料和笔记。
3. 搜索型 AI：找最新资料和引用。
4. 代码 AI：陪你做练习项目。

### 自动化组合

1. 小龙虾 / OpenClaw：接消息渠道和插件。
2. 通用模型：负责理解和规划。
3. 搜索模型：负责查资料。
4. 本地脚本：负责稳定执行重复任务。

## 不同 AI 的使用重点

| 工具 | 更适合 | 使用建议 |
| --- | --- | --- |
| ChatGPT | 综合任务、数据分析、写作、编程 | 当主力助手 |
| Claude | 长文、文档、复杂代码理解 | 多给背景，让它做深度分析 |
| Gemini | Google 生态、长上下文、多媒体 | 配合 Drive、Docs、NotebookLM |
| Perplexity | 搜索、调研、引用来源 | 查资料先用它 |
| Kimi | 中文长文、资料阅读、搜索 | 中文资料和长文档很适合 |
| Cursor | 在编辑器里写代码 | 小白程序员优先上手 |
| Copilot | 代码补全和开发辅助 | 日常编码很稳 |
| Claude Code | 命令行 Agent、项目级修改 | 适合会 Git 的开发者 |
| Codex CLI | 命令行编码任务 | 适合让 AI 读写项目并验证 |
| 小龙虾 / OpenClaw | 本地自动化、消息入口、插件 | 先小权限测试，再逐步放开 |

## 常见错误

### 问题太空

错误：

```text
帮我写一篇 AI 文章。
```

更好：

```text
帮我写一篇给 AI 小白看的文章，主题是 AI 工具怎么选。读者是没有技术背景的人。要求用 Markdown，分成概念、价格、推荐、避坑四部分。
```

### 一次要求太多

错误：

```text
帮我做一个完整网站，顺便写后端、数据库、部署、SEO、支付。
```

更好：

```text
先帮我设计首页结构和技术方案，不要写代码。确认后再开始实现第一版。
```

### 不给资料

错误：

```text
帮我优化这个项目。
```

更好：

```text
这是项目目录和 package.json。请先判断项目技术栈、启动命令、可能的优化点。先不要改文件。
```

### 不检查结果

AI 会犯错，尤其是价格、政策、法律、医学、代码安全、最新版本。越重要的内容，越要人工确认。

## 一个实用工作流

如果你不知道怎么开始，可以按这个流程：

1. 先问：“我这个任务适合用哪类 AI？”
2. 让 AI 帮你拆步骤。
3. 只执行第一步。
4. 检查结果。
5. 再继续下一步。

示例：

```text
我要完成【任务】。请先判断这个任务更适合用聊天 AI、搜索 AI、编程 AI、图片 AI 还是自动化 Agent。然后给我一个 5 步以内的执行流程。
```

## 最后建议

AI 不是一次性给你完美答案的机器，更像一个可以快速试错的助手。小白刚开始不要追求“最强模型”，先把三个习惯练出来：目标说清楚、资料给完整、结果会检查。

等你能稳定把任务拆清楚，再去升级套餐、接 Agent、写 Skill、装小龙虾，这些工具才会真正变成效率提升，而不是新的折腾成本。
