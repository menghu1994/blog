nestjs request life

Nestjs 请求执行顺序

  1. 中间件(Middleware)

    处理请求和响应的原始对象。用于执行跨领域的任务，如日志记录、请求解析（例如 body-parser）、CORS、速率限制等。

  • 可以访问请求 (Request) 和响应 (Response) 对象。
  • 可以结束请求-响应周期（例如，身份验证失败直接返回 401）。
  • 可以调用 next() 将控制权传递给下一个中间件。
  • 绑定层次：全局 -> 模块级 -> 控制器级 -> 路由级。执行顺序也是按这个层次。
  1. 守卫(Guard)

    决定一个请求是否应该被路由程序处理，如角色、权限、ACL等来批准或拒绝请求

  • 可以访问 ExecutionContext（执行上下文），这意味着你可以获取到将要调用的控制器类和处理程序方法。
  • 返回一个布尔值。如果返回 false，NestJS 将拒绝该请求并返回一个 403 Forbidden 错误。
  • 绑定层次：全局 -> 控制器级 -> 路由级。执行顺序也是按这个层次。
  1. 拦截器(Interceptor)

    在方法执行前后绑定额外的逻辑(记录时间，缓存结果等)
    转换函数返回的结果
    转换函数抛出的异常
    扩展基本函数行为(实现重试逻辑等)

  • 可以访问 ExecutionContext 和 CallHandler。
  • 通过 CallHandler 的 handle() 方法，你可以调用路由处理程序。在 handle() 之前写的代码是“前置”逻辑，之后写的代码是“后置”逻辑，形成了一个“包裹”结构。
  • 绑定层次：全局 -> 控制器级 -> 路由级。执行顺序也是按这个层次。
  1. 管道(Pipe)

    转换输入的数据(字符转数字等),添加输入验证

  • 通常作用于特定的参数。
  • 可以访问被装饰的参数的相关元数据（例如，通过 @Body() 传入的数据）。
  • 如果验证失败，会抛出一个由异常过滤器处理的异常。
  • 绑定层次：全局 -> 控制器级 -> 路由级 -> 参数级。执行顺序也是按这个层次。
  1. 控制器(Controller) —> 后置逻辑

    在路由处理程序完成执行后，拦截器的“后置”逻辑会运行。它可以转换从路由处理程序返回的结果。

  • 拦截器是“包裹”着路由处理程序的，所以返回的数据会经过拦截器的 pipe 操作。
  1. 异常过滤器(Filter)

    在整个请求生命周期的任何阶段，如果抛出了未被处理的异常，异常过滤器就会捕获它。
    捕获并处理抛出的异常。它负责生成并发送最终的客户端响应

  • 可以控制响应的格式。
  • 可以针对特定类型的异常（例如 HttpException、自定义异常）进行定制。
  • 绑定层次：全局 -> 控制器级 -> 路由级。NestJS 会使用最具体的（即范围最小的）匹配过滤器。
